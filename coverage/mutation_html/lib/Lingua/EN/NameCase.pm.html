  338: 
  339: =over 4
  340: 
  341: =item * A scalar is never changed in place
  342: 
  343: C<NameCase(\$name)> and C<nc(\$name)> read the string and return a new
  344: one.  Always use the return value:  C<$name = nc($name);>.
  345: Only an I<array reference> is changed in place.
  346: 
  347: =item * Empty and undefined input
  348: 
  349: C<undef>, an empty string and the string "0" are returned as they are.
  350: No warning is given.  Check for C<undef> yourself if you need to know.
  351: 
  352: =item * Switches are global
  353: 
  354: The four switches are package variables.  If you change one, it changes for
  355: the whole program until you change it back.  Use C<local> inside a block
  356: to limit the change.
  357: 
  358: =item * Only the last word can be a post-nominal
  359: 
  360: "JANE PHD SMITH" is not changed to "Jane PhD Smith".  "SMITH PHD" is
  361: changed to "Smith PhD".
  362: 
  363: =item * One name per string, with no extra text
  364: 
  365: "MR. AND MRS. SMITH" and similar text get the same treatment as a name.
  366: Words like "Of" are not changed to "of".
  367: 
  368: =item * The result is a guess
  369: 
  370: Some names are cased wrongly.  For example "MACINNES" becomes "Macinnes".
  371: Check important data by hand.  See L</LIMITATIONS>.
  372: 
  373: =item * Wrong number of arguments
  374: 
  375: C<nc> takes at most one argument.  C<NameCase> in scalar context takes
  376: exactly one.  Anything else stops the program with an error message,
  377: so wrap the call in C<eval> if the input is not trusted.
  378: 
  379: =item * Untrusted input
  380: 
  381: Set C<$Lingua::EN::NameCase::MAX_LENGTH> when names come from users.  Without
  382: it, a very large string is processed in full, using memory in proportion to
  383: its size.  A class name in an error message is shortened and any odd
  384: character in it becomes "?".
  385: 
  386: =item * C<nc()> with no argument uses C<$_>
  387: 
  388: This is the same as the built-in C<lc>.  It can surprise you inside a loop.
  389:

  441: =head2 NameCase
  442: 
  443: Takes a scalar, scalarref, array or arrayref, and changes the case of the
  444: contents, as appropriate. Essentially a wrapper around nc().
  445: 
  446: =head3 PURPOSE
  447: 
  448: Case one name, or a whole list of names, in one call.
  449: 
  450: =head3 ARGS
  451: 
  452: One scalar, one scalar reference, one array reference, or (in list context
  453: only) a list of scalars.
  454: 
  455: =head3 RETURNS
  456: 
  457: =over 4
  458: 
  459: =item * List context with a list, or an array reference
  460: 
  461: A list of name-cased copies.  The source is not modified.
  462: 
  463: =item * Scalar or void context with an array reference
  464:

  926: =head1 SECURITY
  927: 
  928: The module only reads and builds strings.  It opens no files, runs no
  929: programs, uses no string C<eval>, and never turns its input into code or
  930: into part of a regular expression.  Notes for programs that use it:
  931: 
  932: =over 4
  933: 
  934: =item * Taint mode
  935: 
  936: Taint is kept: a name that is tainted gives a tainted result.  The module
  937: never launders data and works under C<perl -T>.
  938: 
  939: =item * Untrusted names
  940: 
  941: Names from users can be very long.  Set C<$Lingua::EN::NameCase::MAX_LENGTH>.
  942: Case mapping can lengthen text: the result is at most three times as long as
  943: the input.  The length check is on the input, before the mapping.
  944: 
  945: =item * Error messages
  946: 
  947: The type or class name of a bad argument is cut to 64 characters and any
  948: character other than a letter, digit, underscore or colon is shown as "?",
  949: so a hostile class name cannot add lines or escape codes to a log.
  950: 
  951: =item * Settings are global
  952: 
  953: The switches, C<$MAX_LENGTH> and C<%MESSAGES> are package variables, so any
  954: code in the same program can change them.  Use C<local>.  They are not a
  955: security boundary.
  956: 
  957: =item * Locked internals
  958: 
  959: L<Sub::Private>, when installed, stops other packages calling the internal
  960: routines.  This is for tidiness, not security; it is switched off when the
  961: environment variable C<HARNESS_ACTIVE> is true, and it is absent when
  962: L<Sub::Private> is not installed.
  963: 
  964: =item * Malformed text
  965: 
  966: Invalid characters (lone surrogates, code points above U+10FFFF) are passed
  967: through without a warning.  Check the encoding of untrusted input before
  968: calling this module.
  969: 
  970: =back

  993: 
  994: Set C<$Lingua::EN::NameCase::MAX_LENGTH> to bound the time spent on any one
  995: name.
  996: 
  997: =head1 LIMITATIONS
  998: 
  999: The design choices below are known weaknesses.
 1000: 
 1001: =over 4
 1002: 
 1003: =item * Global configuration
 1004: 
 1005: C<$HEBREW>, C<$SPANISH>, C<$ROMAN> and C<$POSTNOMINAL> are package
 1006: variables, so one part of a program changing them changes the result for
 1007: all of it.  Use C<local> to scope a change.  A per-call options hash would
 1008: be better, but would change the API.
 1009: 
 1010: =item * Scalar references are not modified in place
 1011: 
 1012: C<NameCase(\$name)> returns a copy.  Changing this would break existing
 1013: callers.
 1014: 
 1015: =item * Exceptions are prefixes
 1016: 
 1017: The "Mac" exceptions match the start of a word, so MacInnes becomes
 1018: Macinnes and MacKenzie becomes Mackenzie.  An exact-surname list would be
 1019: more accurate but needs data this module does not have.
 1020: 
 1021: =item * Everything is an English-language heuristic
 1022: 
 1023: Names are not cased by a grammar.  "Ben" and "Van" are lowercased only when
 1024: they follow another word, and every word of a name is treated alike
 1025: (C<Estate Of Laura Jones>).  For real name parsing use
 1026: L<Lingua::EN::NameParse>.
 1027: 
 1028: =item * Locale is ignored
 1029: 
 1030: Case rules are the Unicode rules, whatever the locale.  Older versions used
 1031: C<use locale>, which gave different answers on different machines.  Data in
 1032: a legacy 8-bit code page must be decoded first (see L</ENCODING>).  Language
 1033: rules are not applied, so Turkish "I" becomes "i", not a dotless "i".
 1034: 
 1035: =item * The Mac test covers the whole string
 1036: 
 1037: Whether the "Mac" rules apply is decided once for the whole string, not word
 1038: by word.  A string that holds both a name such as "Mcdonald" and a name such
 1039: as "Macchiato" will have both treated as Mac names.  Pass one name at a time.
 1040: 
 1041: =item * Hebrew particles need one space
 1042: 
 1043: "ben" and "bat" are recognised only when exactly one white space character
 1044: separates them from the word in front.
 1045: 
 1046: =item * Post-nominals only at the end
 1047: 
 1048: Only the last word is checked, and the list is not exhaustive.
 1049: Since the entries are now matched literally, "MCh." and "FCSP." require
 1050: their final dot (the dot used to match any character).
 1051: 
 1052: =item * Error messages
 1053: 
 1054: Messages are English templates with C<{name}> placeholders, replaceable
 1055: through C<%MESSAGES>.  There is no plural or gender handling because none
 1056: of the messages needs it.
 1057: 
 1058: =item * Encapsulation
 1059: 
 1060: The internal routines are guarded with L<Sub::Private> in enforce mode, but
 1061: only if that module is installed.  It is optional because it needs Perl 5.14
 1062: or later and heavy dependencies; without it the internals are ordinary
 1063: subroutines whose names start with an underscore.  L<Sub::Protected> is not
 1064: used because the module has no classes or methods to protect.
 1065: 
 1066: =back
 1067: 
 1068: =head1 BUGS
 1069: 
 1070: The module covers the rules that I know of. There are probably a lot
 1071: more rules, exceptions etc. for "Western"-style languages which could be
 1072: incorporated.
 1073: 
 1074: There are probably lots of exceptions and problems - but as a general
 1075: data 'cleaner' it may be all you need.
 1076: 
 1077: Use Kim Ryan's L<Lingua::EN::NameParse> for any really sophisticated name parsing.

 1192: =head1 STATE DIAGRAM
 1193: 
 1194: The module keeps no data between calls except the configuration.  So there
 1195: are two small machines: the configuration, and what happens during one call.
 1196: 
 1197: Configuration (the four switches, C<$MAX_LENGTH> and C<%MESSAGES>):
 1198: 
 1199: 	  use Lingua::EN::NameCase
 1200: 	            |
 1201: 	            v
 1202: 	   +-----------------+   set a switch or %MESSAGES key   +-----------------+
 1203: 	   |    DEFAULTS     |---------------------------------->|   CUSTOMISED    |
 1204: 	   | HEBREW=1        |   action: later calls use it      | any switch or   |
 1205: 	   | SPANISH=0       |<----------------------------------| message differs |
 1206: 	   | ROMAN=1         |   set back, or leave a block      +-----------------+
 1207: 	   | POSTNOMINAL=1   |   that used "local"                  |          ^
 1208: 	   +-----------------+                                      +----------+
 1209: 	                                                            set again
 1210: 
 1211: DEFAULTS also means that C<$MAX_LENGTH> is C<undef> and C<%MESSAGES> is
 1212: empty.  Both states accept every call below.  Calls never change the
 1213: configuration.
 1214: 
 1215: One call to C<nc> or C<NameCase>:
 1216: 
 1217: 	 nc(...) / NameCase(...)
 1218: 	        |
 1219: 	        v
 1220: 	  +------------+  bad type, wrong count   +----------+
 1221: 	  | VALIDATING |------------------------->|  FAILED  |
 1222: 	  +------------+  action: croak with the  +----------+
 1223: 	        |         message (usage_nc,       (the caller
 1224: 	        | ok      usage_namecase,           gets an
 1225: 	        v         single_arg)               exception)
 1226: 	  +------------+  undef, "" or "0"        +----------+
 1227: 	  |  READING   |------------------------->|   DONE   |
 1228: 	  +------------+  action: return it as is +----------+
 1229: 	        |                                       ^
 1230: 	        | has text                              |
 1231: 	        v                                       |
 1232: 	  +------------+  base case, Mc/Mac, particles,  |
 1233: 	  |   CASING   |  roman numerals (if ROMAN),     |
 1234: 	  +------------+  post-nominal (if POSTNOMINAL)  |
 1235: 	        |                                       |
 1236: 	        +---------------------------------------+
 1237: 	          action: return the new string

 1239: 	  READING also goes to FAILED when $MAX_LENGTH is set and the text is
 1240: 	  longer (message too_long).  The caller gets an exception and nothing
 1241: 	  is changed.
 1242: 
 1243: 	  NameCase only: an array ref in scalar or void context goes from
 1244: 	  CASING to DONE after replacing each element (the only side effect
