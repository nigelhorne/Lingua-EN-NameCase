  341: =over 4
  342: 
  343: =item * A scalar is never changed in place
  344: 
  345: C<NameCase(\$name)> and C<nc(\$name)> read the string and return a new
  346: one.  Always use the return value:  C<$name = nc($name);>.
  347: Only an I<array reference> is changed in place.
  348: 
  349: =item * Empty and undefined input
  350: 
  351: C<undef>, an empty string and the string "0" are returned as they are.
  352: No warning is given.  Check for C<undef> yourself if you need to know.
  353: 
  354: =item * Switches are global
  355: 
  356: The four switches are package variables.  If you change one, it changes for
  357: the whole program until you change it back.  Use C<local> inside a block
  358: to limit the change.
  359: 
  360: =item * Only the last word can be a post-nominal
  361: 
  362: "JANE PHD SMITH" is not changed to "Jane PhD Smith".  "SMITH PHD" is
  363: changed to "Smith PhD".
  364: 
  365: =item * One name per string, with no extra text
  366: 
  367: "MR. AND MRS. SMITH" and similar text get the same treatment as a name.
  368: Words like "Of" are not changed to "of".
  369: 
  370: =item * The result is a guess
  371: 
  372: Some names are cased wrongly.  For example "MACINNES" becomes "Macinnes".
  373: Check important data by hand.  See L</LIMITATIONS>.
  374: 
  375: =item * Wrong number of arguments
  376: 
  377: C<nc> takes at most one argument.  C<NameCase> in scalar context takes
  378: exactly one.  Anything else stops the program with an error message,
  379: so wrap the call in C<eval> if the input is not trusted.
  380: 
  381: =item * Untrusted input
  382: 
  383: Set C<$Lingua::EN::NameCase::MAX_LENGTH> when names come from users.  Without
  384: it, a very large string is processed in full, using memory in proportion to
  385: its size.  A class name in an error message is shortened and any odd
  386: character in it becomes "?".
  387: 
  388: =item * C<nc()> with no argument uses C<$_>
  389: 
  390: This is the same as the built-in C<lc>.  It can surprise you inside a loop.
  391: 
  392: =back

  443: =head2 NameCase
  444: 
  445: Takes a scalar, scalarref, array or arrayref, and changes the case of the
  446: contents, as appropriate. Essentially a wrapper around nc().
  447: 
  448: =head3 PURPOSE
  449: 
  450: Case one name, or a whole list of names, in one call.
  451: 
  452: =head3 ARGS
  453: 
  454: One scalar, one scalar reference, one array reference, or (in list context
  455: only) a list of scalars.
  456: 
  457: =head3 RETURNS
  458: 
  459: =over 4
  460: 
  461: =item * List context with a list, or an array reference
  462: 
  463: A list of name-cased copies.  The source is not modified.
  464: 
  465: =item * Scalar or void context with an array reference
  466:

  928: 
  929: The module only reads and builds strings.  It opens no files, runs no

  934: 
  935: =item * Taint mode
  936: 
  937: Taint is kept: a name that is tainted gives a tainted result.  The module
  938: never launders data and works under C<perl -T>.
  939: 
  940: =item * Untrusted names
  941: 
  942: Names from users can be very long.  Set C<$Lingua::EN::NameCase::MAX_LENGTH>.
  943: Case mapping can lengthen text: the result is at most three times as long as
  944: the input.  The length check is on the input, before the mapping.
  945: 
  946: =item * Error messages
  947: 
  948: The type or class name of a bad argument is cut to 64 characters and any
  949: character other than a letter, digit, underscore or colon is shown as "?",
  950: so a hostile class name cannot add lines or escape codes to a log.
  951: 
  952: =item * Settings are global
  953: 
  954: The switches, C<$MAX_LENGTH> and C<%MESSAGES> are package variables, so any
  955: code in the same program can change them.  Use C<local>.  They are not a
  956: security boundary.
  957: 
  958: =item * Locked internals
  959: 
  960: L<Sub::Private>, when installed, stops other packages calling the internal
  961: routines.  This is for tidiness, not security; it is switched off when the
  962: environment variable C<HARNESS_ACTIVE> is true, and it is absent when
  963: L<Sub::Private> is not installed.
  964: 
  965: =item * Malformed text
  966: 
  967: Invalid characters (lone surrogates, code points above U+10FFFF) are passed
  968: through without a warning.  Check the encoding of untrusted input before
  969: calling this module.

  995: Set C<$Lingua::EN::NameCase::MAX_LENGTH> to bound the time spent on any one
  996: name.
  997: 
  998: =head1 LIMITATIONS
  999: 
 1000: The design choices below are known weaknesses.
 1001: 
 1002: =over 4
 1003: 
 1004: =item * Global configuration
 1005: 
 1006: C<$HEBREW>, C<$SPANISH>, C<$ROMAN> and C<$POSTNOMINAL> are package
 1007: variables, so one part of a program changing them changes the result for
 1008: all of it.  Use C<local> to scope a change.  A per-call options hash would
 1009: be better, but would change the API.
 1010: 
 1011: =item * Scalar references are not modified in place
 1012: 
 1013: C<NameCase(\$name)> returns a copy.  Changing this would break existing
 1014: callers.
 1015: 
 1016: =item * Exceptions are prefixes
 1017: 
 1018: The "Mac" exceptions match the start of a word, so MacInnes becomes
 1019: Macinnes and MacKenzie becomes Mackenzie.  An exact-surname list would be
 1020: more accurate but needs data this module does not have.
 1021: 
 1022: =item * Everything is an English-language heuristic
 1023: 
 1024: Names are not cased by a grammar.  "Ben" and "Van" are lowercased only when
 1025: they follow another word, and every word of a name is treated alike
 1026: (C<Estate Of Laura Jones>).  For real name parsing use
 1027: L<Lingua::EN::NameParse>.
 1028: 
 1029: =item * Locale is ignored
 1030: 
 1031: Case rules are the Unicode rules, whatever the locale.  Older versions used
 1032: C<use locale>, which gave different answers on different machines.  Data in
 1033: a legacy 8-bit code page must be decoded first (see L</ENCODING>).  Language
 1034: rules are not applied, so Turkish "I" becomes "i", not a dotless "i".
 1035: 
 1036: =item * The Mac test covers the whole string
 1037: 
 1038: Whether the "Mac" rules apply is decided once for the whole string, not word
 1039: by word.  A string that holds both a name such as "Mcdonald" and a name such
 1040: as "Macchiato" will have both treated as Mac names.  Pass one name at a time.
 1041: 
 1042: =item * Hebrew particles need one space
 1043: 
 1044: "ben" and "bat" are recognised only when exactly one white space character
 1045: separates them from the word in front.
 1046: 
 1047: =item * Post-nominals only at the end
 1048: 
 1049: Only the last word is checked, and the list is not exhaustive.
 1050: Since the entries are now matched literally, "MCh." and "FCSP." require
 1051: their final dot (the dot used to match any character).
 1052: 
 1053: =item * Error messages
 1054: 
 1055: Messages are English templates with C<{name}> placeholders, replaceable
 1056: through C<%MESSAGES>.  There is no plural or gender handling because none
 1057: of the messages needs it.
 1058: 
 1059: =item * Encapsulation
 1060: 
 1061: The internal routines are guarded with L<Sub::Private> in enforce mode, but
 1062: only if that module is installed.  It is optional because it needs Perl 5.14
 1063: or later and heavy dependencies; without it the internals are ordinary
 1064: subroutines whose names start with an underscore.  L<Sub::Protected> is not
 1065: used because the module has no classes or methods to protect.
 1066: 
 1067: =back
 1068: 
 1069: =head1 BUGS
 1070: 
 1071: The module covers the rules that I know of. There are probably a lot
 1072: more rules, exceptions etc. for "Western"-style languages which could be
 1073: incorporated.
 1074: 
 1075: There are probably lots of exceptions and problems - but as a general
 1076: data 'cleaner' it may be all you need.
 1077: 
 1078: Use Kim Ryan's L<Lingua::EN::NameParse> for any really sophisticated name parsing.
